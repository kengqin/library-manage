# 多语言（i18n）实施方案

## 1. 目标与范围

| 项目 | 结论 |
| --- | --- |
| 已落地语言 | **18 种**：简体中文（`zh-CN`，源语言）、繁體中文（`zh-TW`）、English（`en-US`）、日本語（`ja-JP`）、한국어（`ko-KR`）、العربية（`ar-SA`）、Čeština（`cs-CZ`）、Deutsch（`de-DE`）、Español（`es-ES`）、Français（`fr-FR`）、Bahasa Indonesia（`id-ID`）、Italiano（`it-IT`）、Polski（`pl-PL`）、Português (Brasil)（`pt-BR`）、Русский（`ru-RU`）、ไทย（`th-TH`）、Türkçe（`tr-TR`）、Tiếng Việt（`vi-VN`） |

## 3. 设计取舍

### 3.1 语义 key，简体中文也进字典

文案以「位置 + 用途」命名，不做成中文原文：

```ts
// packages/i18n/src/messages/zh-CN.ts
export const zhCN = {
  'common.save': '保存',
  'library.import.doneCount': '已导入 {count} 本书'
}

// 组件里
showGlobalMessage(t('library.import.doneCount', { count: importedIds.length }))
```

理由：

- **文案与代码解耦**：改措辞只动 `zh-CN.ts`，不用在 60 多个组件里找字符串；简体同样可以只靠改字典来维护。
- **key 稳定**：中文原文当 key 时，改一个字就得同步改 18 份字典里的 key；现在 key 不动，只改值。
- **类型安全**：`MessageKey = keyof typeof zhCN`，`t()` 只接受这个联合类型，写错 key 在 `vue-tsc` 阶段就报错，不用等运行时。
- **分组可读**：字典按 `common / app / window / library / contents / reader / import / notes / editor / search / online / downloads / browser / ide / update / storage / settings / mobile` 分块，新文案按块追加。

代价：新增文案要同时在 18 份字典各写一行（漏一份会被 `i18n:check` 逐条列出来并让测试链失败）。

### 3.2 插值而不是字符串拼接

带变量的文案整句翻译，占位符用 `{name}`，各语言必须保留同名占位符：

```ts
t('library.import.doneCount', { count: 6 })   // 已导入 6 本书 / Imported 6 books
```

中文与英文语序不同，把 `{{ n }} 本` 拆开分别翻译会得到 “Matched books 12 books”。凡是有数量的位置都是整句 + 参数，例如书籍卡片、目录计数、版本号、备份结果。

斯拉夫语系（俄/波/捷）有复数变格，文案统一写成「不随数变化」的形式（`Импортировано книг: {count}`、`Zaimportowano książek: {count}`），避免 2 本 / 5 本 各自变形的语法错误。

### 3.3 语言状态必须是响应式的

- 模板里的 `t()` 直接调用即可，切换语言会触发重渲染。
- **setup 期算好的常量不会跟着变**，例如侧栏导航项、设置页的下拉选项、搜索引擎名称，都已改为 `computed`（引擎名称改为存 key，渲染时 `t(option.label)`）。
- 服务层（`online-library.ts`、`release-center.ts` 等）在报错瞬间取当前语言，历史消息保留当时的语言，属预期行为。

### 3.4 持久化与多窗口

- 存储键：`novel-library:locale`（与 `novel-library:appearance` 并列）。
- 首次启动按「系统语言 → 本机时区 → 中文」判定（见 3.6），命中的结果落盘，保证下次稳定。
- 桌面端主窗口、设置窗口、内置浏览器是不同 webview，通过 `storage` 事件同步，无需重启。
- 同时同步 `<html lang>`、`dir`、`data-locale` 与 `data-locale-source`（判定来源，便于排查），方便无障碍读屏与按语言做样式微调。

### 3.5 语言标记的匹配顺序

`LOCALE_PREFIXES` 是**有序**表，前缀短的不能排在更具体的前面，繁体必须排在 `zh` 之前：

```ts
['zh-hant', 'zh-TW'], ['zh-tw', 'zh-TW'], ['zh-hk', 'zh-TW'], ['zh-mo', 'zh-TW'], ['zh', 'zh-CN']
```

否则浏览器报 `zh-Hant`、`zh-TW` 时会被大陆中文先吃掉。同理 `id` 与 `in`（印尼语旧标记）都指向 `id-ID`，且都排在 `it` 之前不影响匹配（两者不是彼此的前缀）。

地区变体统一归到主变体：`en-GB` → `en-US`、`es-419` → `es-ES`、`fr-CA` → `fr-FR`、`de-AT`/`de-CH` → `de-DE`、`pt-PT` → `pt-BR`、`ar-EG` → `ar-SA`、`cs-SK` → `cs-CZ`、`ko-KP` → `ko-KR`。

### 3.6 默认界面语言的判定顺序

首次启动（`localStorage` 里没有用户选择）时，按 **系统语言 → 本机时区 → 简体中文** 三层判定，前一层命中就不再看下一层。实现收敛在 `packages/i18n/src/index.ts` 的 `resolveLocale({ languages, timeZone })`，返回 `{ locale, reason, matched }`，`reason` 为 `system-language` / `time-zone` / `fallback`，同时写进 `<html data-locale-source>` 便于排查。

| 顺序 | 依据 | 取值来源 | 命中条件 | `reason` |
| --- | --- | --- | --- | --- |
| 1 | 系统语言 | `navigator.languages`（按偏好顺序）→ `navigator.language` → 旧 Edge 的 `navigator.userLanguage` → `Intl.DateTimeFormat().resolvedOptions().locale`（仅兜底：Firefox 装语言包时它与系统区域不一致） | 标记能归一到 18 种受支持语言 | `system-language` |
| 2 | 本机时区 | `Intl.DateTimeFormat().resolvedOptions().timeZone`（IANA 标记） | 命中 `TIME_ZONE_LOCALES` 精确表或 `TIME_ZONE_PREFIXES` 前缀表 | `time-zone` |
| 3 | 默认 | 常量 `DEFAULT_LOCALE` | 恒成立 | `fallback` |

受支持的 18 种语言即 `SUPPORTED_LOCALES`：`zh-CN`（源语言）、`zh-TW`、`en-US`、`ja-JP`、`ko-KR`、`ar-SA`、`cs-CZ`、`de-DE`、`es-ES`、`fr-FR`、`id-ID`、`it-IT`、`pl-PL`、`pt-BR`、`ru-RU`、`th-TH`、`tr-TR`、`vi-VN`。

**时区 → 语言映射规则**（`TIME_ZONE_LOCALES`，键为全小写 IANA 标记）：

| 语言 | 收录时区（节选） |
| --- | --- |
| `zh-CN` | `Asia/Shanghai`、`Asia/Chongqing`、`Asia/Harbin`、`Asia/Urumqi`、`Asia/Kashgar`、`PRC` |
| `zh-TW` | `Asia/Taipei`、`Asia/Hong_Kong`、`Asia/Macau`、`ROC`、`Hongkong` |
| `ja-JP` / `ko-KR` | `Asia/Tokyo` / `Asia/Seoul`、`Asia/Pyongyang`、`ROK` |
| `vi-VN` / `id-ID` | `Asia/Ho_Chi_Minh`、`Asia/Saigon` / `Asia/Jakarta`、`Asia/Makassar`、`Asia/Jayapura`、`Asia/Pontianak` |
| `th-TH` | `Asia/Bangkok`（泰国全境单一时区） |
| `ar-SA` | 海湾与黎凡特（`Asia/Riyadh`、`Asia/Dubai`、`Asia/Baghdad`、`Asia/Amman`…）+ 北非（`Africa/Cairo`、`Africa/Algiers`、`Africa/Casablanca`…） |
| `de-DE` / `fr-FR` / `it-IT` | 德奥瑞列（`Europe/Berlin`、`Europe/Vienna`、`Europe/Zurich`…）/ 法国与法语非洲（`Europe/Paris`、`Africa/Dakar`、`Africa/Kinshasa`…）/ `Europe/Rome`、`Europe/Malta` |
| `es-ES` | 西班牙本土 + 墨西哥、哥伦比亚、秘鲁、智利、阿根廷、乌拉圭、委内瑞拉、中美洲 |
| `pt-BR` | 巴西全境 + 葡萄牙（`Europe/Lisbon`）+ 安哥拉、莫桑比克等 |
| `ru-RU` | 俄罗斯全境 + 白俄、哈萨克斯坦、中亚 |
| `tr-TR` / `pl-PL` / `cs-CZ` | `Europe/Istanbul` / `Europe/Warsaw` / `Europe/Prague` |
| `en-US` | 英伦三岛、北美、大洋洲（前缀 `Australia/*` 兜住全境）、`Asia/Singapore`、`Asia/Kolkata`、`Asia/Manila`、`Asia/Karachi`、英语官方的非洲国家 |

几条硬规则：

1. **只收「该地区确有受支持语言作为主要界面书面语」的时区**。多语言地区按实际使用习惯取一门（新加坡、印度、菲律宾、加拿大 → `en-US`）。
2. **不做地理硬猜**：语言不受支持且时区未收录（`Asia/Yangon`、`Asia/Phnom_Penh`、`Africa/Addis_Ababa`、`UTC`）一律视为「无法匹配」，落到中文，而不是按邻国推一门语言。
3. **整片区域语言一致时用前缀**，避免上百条枚举：`Australia/*` → `en-US`、`America/Argentina/*` → `es-ES`，按最长前缀优先命中。
4. 匹配前只做去空白 + 转小写；`Asia/Ho_Chi_Minh` 的下划线是名字的一部分，**不能**像语言标记那样替换成连字符。
5. 兼容少量遗留时区 ID（`PRC`、`ROC`、`ROK`、`Hongkong`、`Singapore`、`Japan`、`GB`、`Eire`），部分老系统与第三方运行时会返回这些名字。

典型判定（单测逐条覆盖）：

| 场景 | 系统语言 | 时区 | 结果 |
| --- | --- | --- | --- |
| 国内 Windows | `zh-Hans-CN` | `Asia/Shanghai` | `zh-CN`（language） |
| 日本用户 | `ja-JP` | `Asia/Tokyo` | `ja-JP`（language） |
| 泰国用户，系统也设成泰语 | `th-TH` | `Asia/Bangkok` | `th-TH`（language） |
| 泰国用户，系统语言是英语 | `en-US` | `Asia/Bangkok` | `en-US`（language） |
| 泰国用户，系统语言是希伯来语 | `he-IL` | `Asia/Bangkok` | `th-TH`（time-zone） |
| 泰语系统，机器在德国 | `th-TH` | `Europe/Berlin` | `th-TH`（language） |
| 希伯来语系统，机器在德国 | `he-IL` | `Europe/Berlin` | `de-DE`（time-zone） |
| 系统信息全取不到 | 无 | 无 | `zh-CN`（fallback） |

**取不到系统信息也必须稳定**：`vue.ts` 的 `readSystemHints()` 对 `navigator`、`Intl`、时区解析分别 `try/catch`，任何一种失效都只意味着少一条线索，函数恒返回 `{ languages, timeZone }` 对象；`resolveLocale()` 无参调用返回 `{ locale: 'zh-CN', reason: 'fallback' }`，不会抛错。原型壳（Tauri / Capacitor）能拿到更准的系统语言时，可通过 `initializeLocale({ systemLanguages })` 传入，排在浏览器线索之前。

### 3.7 各端入口的布局约束

- 桌面端用 `UiSelect`，菜单 `max-height: 280px` + 滚动，18 项内容约 515px、视口内可见 10 项，超出部分滚动，菜单底部约 508px 仍在 820px 窗口内，无裁切。
- 移动端语言按钮为两列网格，18 项排成 9 行（列表高约 458px），390px 宽度下每项 172.5×40，无省略号、无横向滚动。
- Web 端左下角是原生 `select`：语言变多时按钮组会横向溢出，下拉在窄屏只占 `52vw`；`Português (Brasil)` 这类长标签也能完整显示。

### 3.8 RTL（阿拉伯语）

- `RTL_LOCALES = new Set(['ar-SA'])`，`localeDirection()` 返回 `rtl`，由 `vue.ts` 写进 `<html dir>`，整页镜像。
- 窗口标题栏固定 `direction: ltr`：最小化/最大化/关闭仍跟随系统习惯停在右上角，不随语言翻转。
- 枚举分隔符按语言切换：中日文用「、」，阿拉伯语用 `، `（U+060C），其余 `, `。
- 选择器与图标方向由浏览器按 `dir` 自动处理；正文左对齐改为右对齐，图表与进度条方向随之翻转。

### 3.9 Web 端（VitePress）的边界

- 组件内文案（首页、专题页、本地书架、阅读设置、主题编辑器）都是普通 Vue 组件，接同一套 `t()`。
- 站点导航与页脚来自 `.vitepress/config.mts` 静态配置，不属于组件。`site-chrome.ts` 改写 `themeConfig` 并把已渲染的导航与「外观」标签重贴一次（VitePress 的 siteData 是浅层 ref，就地改写不会触发重渲染），同时在每次更新后写回 `<html lang/dir>`（水合会用配置里的 `lang` 覆盖）。
- 首页大标题由「小说 + 书库」两段拼成，中文与日文不留空格，其余语言自动补一个词间隔（`titleGap`）。
- 书名为内容层数据，导航里的书名保持原样。

## 4. 新增文案 / 新增语言的流程

新增文案：

1. 源码里写 `t('area.thing')`，带变量就用 `{name}` 占位。
2. 在 `messages/zh-CN.ts` 对应分组补一行中文（同时决定 key 是否存在），再在其余 17 份字典各补一行。
3. 跑 `npm run i18n:check`，必须输出「文案齐全（…）」。缺某条 key 会逐条列出并退出码 1。

新增语言（以本次 11 种为样板）：

1. `packages/i18n/src/messages/xx-XX.ts`：照抄 `zh-CN.ts` 的 key 与分组顺序，逐条填译文；只保留 `// ── 分组 ──` 注释，条目一律单行 `'key': '译'`。
2. `index.ts`：`Locale` 联合类型加 `'xx-XX'`，`SUPPORTED_LOCALES` 加一项（label 用该语言自称，位置按「中文 → 英日韩 → 其余字母序」插入），`MESSAGES` 加映射，`LOCALE_PREFIXES` 加前缀（注意顺序）。
3. 补齐默认语言的判定线索：`TIME_ZONE_LOCALES` 加该语言主要通行的时区（没有就留空，系统语言仍能命中），必要时给 `TIME_ZONE_PREFIXES` 加前缀规则。
4. 三端入口都由 `SUPPORTED_LOCALES` 自动渲染，界面无需改动；`<html lang>`、`localStorage`、系统语言/时区推断也自动跟随。
5. 若枚举分隔符不是顿号/逗号，补一下 `vue.ts` 的 `listSeparator()`。
6. 若是从右到左书写的语言，把 locale 加进 `index.ts` 的 `RTL_LOCALES`，并检查侧栏、进度条、图标方向的镜像（见 3.8）。
7. 用 `.tools/check-dict.mjs xx-XX` 自查条目数与占位符，再跑第 5 节的全套校验。

译文的落词约定（本次统一执行）：按钮用不定式/名词式（Speichern、Salvar、Сохранить、Lưu、حفظ），正文用各语言的正式敬语体；书架、书库、章节、批注、书签、导入、导出、设置这组术语在每种语言里固定一种译法并贯彻全篇；PDF、EPUB、JSON、URL、Markdown、GitHub 与搜索引擎品牌名保持原样。

## 5. 校验与测试

```bash
npm run i18n:check              # 源码 key vs 18 份字典 + 词条一一对应 + 旧写法检查
npm run i18n:check -- --verbose # 额外列出未被静态引用的 key
npx vitest run packages/i18n
npm test                        # 已把 i18n:check 串到测试链末尾
```

校验脚本会拦三类问题：① 源码用到的 key 某语言缺失；② 某语言词条集合与 `zh-CN` 不一致；③ 源码里又出现 `t('中文原文')` 的旧写法。

单测覆盖（33 项）：各语言标记及地区变体归一（含 `zh-Hant`/`zh-HK` → `zh-TW`、`pt-PT` → `pt-BR`、`in-ID` → `id-ID`）、按浏览器偏好顺序推断、时区映射（中国四地、日韩、东南亚、阿语区、欧洲、拉美、前缀规则、大小写与空白归一、未收录时区返回 `undefined`）、三层优先级的完整矩阵（语言优先于时区、语言全不支持时走时区、两者皆不中回中文、系统信息全缺失仍回中文）、插值（含未知占位符）、18 种语言逐条命中字典、未知 key 回退、各语言占位符与原文一致、空译文拦截、各语言词条集合与 `zh-CN` 完全一致、`ar-SA` 为 `rtl` 其余为 `ltr`。

## 8. 已知边界（下一步可做）
1. **抛错文案**：parser、EPUB、备份等模块仍有约 30 处 `throw new Error('中文…')`，异常会经 `userFacingError` 透出给用户。搜索模块两条已改成 key，其余建议统一改成错误码 + 前端映射。
2. **Worker 生成的进度文案**：`parse-epub.ts` 在 Worker 内运行，无法读取界面语言，EPUB 导入的阶段提示仍是中文。要彻底解决需把「进度码 + 参数」回传主线程再翻译。
3. **Rust 侧返回的文案**：如 IDE 插件清单里的名称与说明、数据库层错误。可在 Tauri 命令里返回码，由前端映射翻译。
4. **VitePress 内置文案**：搜索框占位等来自 VitePress 自带语言包，跟随 `config.mts` 的 `lang`；已覆盖 `docFooter`、`darkModeSwitchLabel`、`sidebarMenuLabel`、`returnToTopLabel` 与移动端「外观」标签。
5. **站点标题**：`config.mts` 的 `title: '小说书库'` 作为品牌名保留原文，浏览器标签页标题不随语言变化；如需本地化，可新增 `web.siteTitle` 并在 `patchNavLabels` 里同步 `document.title`。
6. **内容层**：书名、简介、分类、连载状态属于书籍数据，不做翻译；首页筛选里的「连载中」由 `book.json` 的 `status` 生成，因此保持中文。
7. **地区变体**：葡语只有巴西变体（`pt-PT` 也归到 `pt-BR`），西语按欧洲西语，阿拉伯语按沙特标准，泰语按曼谷（中部泰语）用法、未区分方言，若需 `pt-PT`、`es-419`、`ar-EG` 等独立措辞，可再拆字典。
8. **IDE 插件内部文案**（VS Code / JetBrains / Visual Studio 面板）不在本次范围。
9. **机器翻译校对**：新增的 11 种语言已按软件界面用语习惯落词并通过结构与术语一致性检查，正式发版前建议请母语使用者抽查阅读器、设置页、导入流程三处高频文案。
10. **时区映射表需要人工维护**：`TIME_ZONE_LOCALES` 是静态白名单，新增语言或新地区时需补条目；现故意不收录语言不受支持的地区（`Asia/Yangon`、`Asia/Phnom_Penh`、`Africa/Addis_Ababa`），这类用户会落到中文。若后续新增印地语、高棉语等语言，同步往表里加时区即可。
11. **系统语言以 WebView 上报为准**：桌面端与移动端都读 `navigator.languages` / `Intl`，未额外走原生接口透传 OS 语言。若遇到系统语言与 WebView 不一致的机型，可由原生壳通过 `initializeLocale({ systemLanguages })` 传入，优先级高于浏览器线索。
